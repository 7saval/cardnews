## ✅ 완료한 작업

### 1. Phase 0 — 보조금24 API 전수 조사, 시리즈를 "마감 임박"에서 "몰랐던 상시 혜택"으로 변경

- 온통청년 청년정책 API는 신청 완료(승인 대기). 공공데이터포털 **"행정안전부_대한민국 공공서비스(혜택) 정보"(보조금24)**는 자동승인이라 이쪽으로 먼저 진행
- `apps/benefit-collector/src/test-gov24.js`로 `serviceList`·`supportConditions` 전체(10,969건)를 받아 집계. 원본은 `output/raw/`에 24시간 캐시

| 확인 항목 | 결과 |
|---|---|
| 필수 필드(서비스명·지원내용·신청기한·지원대상·URL·기관) 채움 | 모두 100% |
| 신청기한이 상시(상시·연중·수시) | 60.8% |
| 연도까지 날짜로 파싱되는 신청기한 | **5.9%** |
| 마감 3~14일 이내 + 청년 + 전국·서울 | **1건** |
| 상시 + 전국·서울 + 청년 포함 | 1,153건 |
| 지원내용 60자 이하 | 32% |

- 결론: **마감 임박 시리즈는 보조금24로는 성립하지 않는다** (날짜 있는 공고가 적고 대부분 시군구). 대신 상시 혜택이 충분해서 **"몰랐던 상시 혜택 N선 (카테고리별)"**로 시리즈를 바꿈. 온통청년이 승인되면 같은 조사 후 마감 임박을 2차로 추가
- 신청기한 자유 텍스트 분류기 `src/lib/period.js` — `dated / yearless / always / budget / reference / no_application / empty / other`. 연도 없는 끝 날짜는 앞 날짜의 연도를 이어받고, 월이 줄면 다음 해로 넘김

### 2. 지역 범위 결정 — 자치구 혜택은 별도 시리즈로

- 처음엔 "서울로 시작하는 기관"을 전부 서울로 잡았는데, 그러면 구청 혜택(서울 자치구)이 섞인다
- 사용자 질문 "구청 혜택도 서울에 포함되잖아?"를 검토: 구청 혜택은 그 구 주민만 받을 수 있어 독자 대부분에게 "나와 상관없는 카드"가 되는데, 수는 전국 혜택과 비슷함(상시+개인+청년 기준 전국 430, 서울시 65, 자치구 385)
- 결정: 카테고리 시리즈는 **전국 + 서울특별시(산하 포함)**, 자치구 혜택은 **"OO구 혜택 모음"(district) 시리즈**로 따로. 지역은 기관 유형이 아니라 **기관명**으로 판별(구 산하 공단도 그 구로 잡히게), 25개 구 모두 잡히는 것 확인

### 3. 스키마 확정

- `shared/schemas/benefit.ts` 신규 — 소스와 무관한 `BenefitRecord`(사실 필드 + `raw` 원문) / `CollectedBenefits`(회차 단위, `series_type`: always·district·deadline)
- `shared/schemas/card-news.ts` 교체 — 장소 필드(`place_name`, `address`, `image_*`) 삭제, 혜택 필드(`benefit`, `target`, `period_end`, `source_name`, `source_url` 등) 추가
- `source_id`는 `<소스>:<ID>` (예: `gov24:B55400900001`) — 온통청년이 붙어도 ID가 안 겹치게
- 샘플 두 개를 **실제 보조금24 데이터 5건**으로 작성(`collected-benefits.example.json`, `card-news.example.json`). 이후 모든 테스트와 렌더 샘플이 이 파일을 공유

### 4. Phase B — "사실은 LLM이 쓰지 않는다" 구현

- **assemble** (`apps/content-generator/src/assemble.js`): LLM 응답 스키마엔 카피 필드(subtitle, caption, benefit, target, 회차 카피)만 두고, 정책명·기관·링크·기한·카테고리는 코드가 `source_id`로 원문에서 주입. 카드 순서·개수도 수집 결과를 따르고, LLM이 카드를 빠뜨리거나 없는 ID를 지어내거나 중복으로 쓰면 에러
- **fact-check** (`src/fact-check.js`): LLM이 쓴 문구의 숫자를 (값, 단위)로 정규화해 원문과 대조
  - 한국어 금액 정규화: `270만원` ↔ `270만 원`, `1,000만원`, `5백만원`, 범위의 단위 이어받기
  - 단위가 있는 숫자는 원문에도 같은 단위가 있어야 통과(`20세`가 원문의 `20%`로 통과하지 않게)
  - "몰랐던 혜택 7선"처럼 회차 카피의 개수가 실제 카드 수와 다르면 실패, 지난 마감일이면 실패
- **재생성**: 문제가 나오면 문제 목록과 이전 응답을 넣어 1회 재생성, 그래도 실패하면 `<out>.failed.json`을 남기고 종료 — 틀린 정보를 내보내는 것보다 낫다
- 실제 데이터로 측정: 사람이 쓴 요약(서비스목적요약) 2,490건에 같은 검사를 돌리면 10.7%가 실패 — 대부분 요약에만 있고 원문엔 없는 숫자라 검사가 맞게 잡은 것
- 테스트 24개 (`fact-check.test.js` 18, `assemble.test.js` 6)

### 5. Phase C — 사진 없는 텍스트 중심 카드

- 배경: 사진 대신 **카테고리별 그라디언트**(10종, `theme.ts`), 커버·CTA는 로고와 같은 브랜드 그라디언트(코랄 → 오렌지)
- 콘텐츠 카드: 카테고리 칩 + 기한 배지(`상시 신청` / `D-n` / `오늘 마감`) → 정책명 → **혜택(가장 크게)** → 대상 → 코멘트 → 출처 기관. 링크는 이미지에서 못 누르니 "원문 링크는 캡션에 ↓"
- CTA: "비공식 큐레이션 · 신청 전 원문 공고를 꼭 확인하세요" + 출처를 데이터와 무관하게 항상 표기 (기관 공식 계정 오인 방지)
- **글자 넘침**: 정책명이 p50 14자, p99 34자로 편차가 커서 크기를 고정하지 않음. `FitText`가 칸에 맞을 때까지 글자를 줄이고, 최소 크기로도 넘치면 **렌더가 실패**하며 넘친 문구를 출력 — 잘린 사실 정보를 내보내지 않기 위해
- 넘침 확인 샘플 `samples/stress.json` (52자 정책명, 25자 기관명, 아주 짧은 문구, D-day 배지)
- `ImageCredit`, `/__images` 미들웨어 제거. 렌더 결과는 `output/benefit/<JSON 이름>/`에 저장해 맛집 시절 결과물·이전 회차와 안 섞이게 함 (맛집 결과물은 정리)

### 6. Phase A — 수집·선별 + LLM 관련성 점수

- 사용자 결정: **농림축산어업은 카테고리 순환에서 제외**, "몰랐던"은 조회수 구간 대신 **LLM 관련성 점수**로
- `npm run collect` 흐름: 원본(캐시) → 정규화 → 공통 조건(상시 · `개인` 대상 · 19~34세 포함 · 전국+서울 · 정책명 50자 이하) → 발행 이력·같은 정책명 제외 → 가장 오래 안 다룬 카테고리부터 → LLM 점수 → 상위 5건
- LLM 점수(`src/lib/relevance.js`): `relevance`(청년이 실제로 받을 수 있고 쓸모 있는가)와 `obscurity`(잘 모를 법한가)를 1~5로. relevance 4 이상 중 합이 높은 순. 30건씩 묻고 빠진 항목은 한 번 더 묻고, `source_id@수정일시`로 캐시해 원문이 안 바뀌면 다시 안 물음
- 발행 이력 `data/published.json`(커밋 대상): **수집이 아니라 발행 뒤에** `npm run mark-published`로 기록 — 생성이 실패한 회차의 혜택이 이력에 남아 영영 안 나오는 일을 막기 위해
- 공통 조건 적용 후 카테고리별 후보: 생활안정 117, 행정·안전 71, 보육·교육 61, 보건·의료 54, 고용·창업 41, 문화·환경 39, 임신·출산 20, 보호·돌봄 20, 주거·자립 12
- 테스트 24개 (`period` 8, `select` 10, `relevance` 5, `history` 1) — API·LLM 없이 돈다

## 🐛 발생한 문제 & 해결

### 문제 1: 보조금24 호출이 `401 등록되지 않은 인증키`

- **원인**: `.env`에 포털의 **Encoding 키**(이미 `%`로 인코딩된 값)를 넣었는데 `URLSearchParams`가 한 번 더 인코딩
- **해결**: 키에 `%`가 있으면 디코딩해서 쓰도록 `getServiceKey()` 수정 — 어느 키를 넣어도 동작

### 문제 2: 계획서의 지역 판별 가정이 실제 값과 다름

- **원인**: `소관기관유형`에 "지방자치단체" 값이 있을 거라 가정했지만 실제 값은 `중앙행정기관 / 공공기관 / 광역시도 / 시군구 / 지방출자_출연기관 / 지방공기업 / 교육청`
- **해결**: 전국은 유형(`중앙행정기관`·`공공기관`)으로, 서울·자치구는 **기관명**으로 판별 (`regionOf`)

### 문제 3: 신청기한 분류에서 `other`가 24.9%

- **원인**: "접수기관 별 상이"(861건), "신청 불필요" 같은 표현을 못 잡음
- **해결**: `no_application` 종류 추가, 공고 참조 키워드 확장 → `other` 대폭 감소

### 문제 4: fact-check가 "몰랐던 혜택 7선"(카드 5장)을 통과시킴

- **원인**: 원문 어딘가에 `7`이 있으면 단위와 상관없이 통과
- **해결**: 단위가 있는 숫자는 원문에도 같은 단위가 있어야 통과하도록 엄격하게 바꾸고, 회차 카피의 개수 단위(선·가지·개·곳·건)는 실제 카드 수와 비교

### 문제 5: 원문 "1/2 일시지급"이 `2일`로 읽힘

- **원인**: 숫자와 단위 사이 공백을 모든 단위에 허용
- **해결**: 공백은 `원`(예: `270만 원`)에만 허용

### 문제 6: 넘침 검사가 한 줄짜리 정책명도 실패시킴

- **원인**: 정책명 칸을 `max-height`로 바꾸자, Noto Sans KR 글리프가 `line-height`보다 커서 자동 높이 박스의 `scrollHeight`가 `clientHeight`보다 항상 몇 px 컸음
- **해결**: `max-height`가 있는 박스는 `max-height`를 한계로 비교. Playwright로 박스별 `scrollHeight/clientHeight`를 찍어 원인 확인

### 문제 7: `npm test`가 조사 스크립트까지 테스트로 실행

- **원인**: `node --test` 기본 패턴이 `test-*.js`도 잡아서 `src/test-gov24.js`(API 호출 스크립트)가 돌았음 — 테스트 수가 24가 아니라 25로 나와서 발견
- **해결**: `node --test "test/**/*.test.js"`로 범위 지정

### 문제 8: 셸 명령이 120초 멈춤 (두 번)

- **원인**: ① Windows의 `python` 스토어 스텁이 입력을 기다림 ② 인자 없는 `cat > 파일`이 표준 입력을 기다림
- **해결**: 둘 다 중단하고 파일 편집 도구·Node 스크립트로 대체, 이후 명령엔 `< /dev/null`

## 💡 배운 점 / 메모

- **만들기 전 전수 조사가 시리즈 자체를 바꿨다.** "마감 임박"은 기획 단계에서 가장 매력적인 아이디어였지만, 실제 데이터로는 한 주에 1건이었다. 대신 조사가 "상시 혜택이 충분하다"는 대안까지 같이 보여줬다
- "LLM이 사실을 안 쓰게" 하는 가장 확실한 방법은 **응답 스키마에서 사실 필드를 빼는 것**이다. 남는 숫자(카피 속 금액)는 원문 대조로 막고, 대조가 못 잡는 것(숫자 없는 거짓말, "100분의 50" ↔ "50%")은 검수 체크리스트로 넘긴다
- 검사기는 **엄격하게 만들고 실제 데이터로 오탐률을 재야** 한다. 사람 요약 10.7% 실패는 대부분 검사가 맞았다 — 오탐률이 아니라 "원문에 없는 숫자가 이만큼 흔하다"는 근거가 됐다
- 렌더러도 "틀린 정보를 내보내느니 실패"를 따른다 — 글자를 잘라 맞추는 대신 넘치면 렌더를 멈춘다. 일부러 길게 만든 샘플이 실패하는 것으로 검사가 동작함을 확인했다
- LLM 점수는 의외의 데이터 품질 문제도 잡는다(데이터에 섞인 테스트 항목). 규칙 필터로는 못 잡는 것
- 이력은 "수집했을 때"가 아니라 "발행했을 때" 기록해야 실패한 회차가 후보를 소진하지 않는다
- 단계별로 커밋을 나눠 두니(조사·스키마 / fact-check / 연결 / 렌더러 / 경로 / 수집기) 각 단계의 근거를 계획서와 커밋에서 따로 찾을 수 있다
