## ✅ 완료한 작업

### 1. 주제 전환 결정 — 맛집 → 청년정책·지원사업 등 "혜택 소식" 큐레이션

- 맛집 카드뉴스는 남의 사진과 리뷰에 의존해서 저작권 문제가 계속 따라왔다. 포트폴리오의 목표는 "워크플로우 자동화 경험"인데, 카드 1건마다 DM으로 사진 허락을 받아야 하는 구조라 자동화 범위가 계속 줄었다
- 주제 선정 기준을 **"사진이 필요 없고, 원천 데이터가 API로 열려 있으며, 재사용 조건이 명확한 것"**으로 잡음
- 1순위로 **청년정책·지원사업 마감 알림 카드뉴스** 채택
  - 공공 API 데이터라 출처 표시 조건으로 쓸 수 있는 경우가 많다 (데이터셋별 공공누리 유형은 확인 필요)
  - 텍스트와 템플릿만으로 카드가 완성돼 이미지 매칭·출처 관리가 사라진다
  - 마감일이 있어 "D-7 자동 발행" 같은 스케줄링에 이유가 생긴다
  - 원문이 구조화 데이터라 LLM 요약의 금액·기간·자격을 자동 검증할 수 있다
- 검토했다가 접은 대안: 개발 트렌드 요약(비슷한 계정이 많음), 데이터 카드(대시보드에 가까움), 내 데브로그 카드뉴스(수집 단계가 없어 파이프라인이 얇음). 도서·영화·여행지는 표지·사진 때문에 같은 문제가 반복돼 제외

### 2. 계정명 변경 영향 범위 조사

- 저장소에서 `matsoozip`/`맛수집`을 전부 검색. 핸들은 대부분 `--handle` 인자로 주입되는 구조라 **동작에 영향을 주는 하드코딩은 `apps/image-matcher/src/find-channels.js`의 `HANDLE` 상수 한 곳**뿐이었다
- 나머지는 로고 파일, alt 텍스트, 주석, README 예시, 기획 문서
- 인스타 계정은 **같은 계정에서 사용자명만 바꾸면** `IG_BUSINESS_ACCOUNT_ID`와 토큰이 그대로라 `.env`와 GitHub Secrets는 손댈 필요가 없다는 점을 확인(새 계정을 만들면 전부 재발급)

## 🐛 발생한 문제 & 해결

### 문제 1: 로고 첫 렌더에서 북마크와 워드마크·불꽃이 겹침

- **원인**: 북마크를 크게 잡아 아래쪽 V자 끝이 "핫" 글자 윗부분에 닿았고, 불꽃 아랫부분도 V자 홈에 붙어 답답해 보였다
- **해결**: 북마크 폭과 높이를 줄이고(폭 260 → 190) 위로 올린 뒤, 불꽃 배율을 1.56 → 1.3으로 낮춰 홈과 간격 확보. 스크래치 폴더에 먼저 렌더해 눈으로 확인한 다음 실제 `logo.png`/`logo.jpg`를 덮어씀
- **참고**: 워드마크 폰트는 렌더러와 같은 Noto Sans KR을 Google Fonts에서 불러옴 — 렌더 스크립트에서 `document.fonts.check`로 실제 로드 여부를 찍어 폴백 폰트로 찍히지 않았는지 확인

## 💡 배운 점 / 메모

- 자동화 프로젝트의 주제는 **"데이터를 가져와도 되는가"**를 먼저 따져야 한다. 맛집은 수집은 쉬웠지만 재게시 권리가 없어서 자동화가 사람의 허락 단계에서 끊겼다
- 계정 정보를 `--handle` 인자로 주입하게 만들어 둔 덕에 계정명 변경의 실제 코드 수정이 한 곳으로 끝났다. LLM이 지어내면 안 되는 값을 코드에서 주입하는 원칙이 변경 비용도 줄여 준다
- 인스타 사용자명 변경과 계정 교체는 다르다 — 사용자명만 바꾸면 비즈니스 계정 ID·토큰이 유지된다
- 로고처럼 단순한 도형 + 글자 조합은 SVG로 직접 쓰는 편이 낫다. 원본이 텍스트라 diff가 보이고, 이미 있는 Playwright로 래스터 변환까지 된다
- 주제를 바꿔도 렌더러·LLM 폴백·인사이트 수집은 그대로 쓴다. 모듈을 단계별로 나눠 둔 구조가 피벗 비용을 줄였다
