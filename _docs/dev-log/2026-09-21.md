### 2. 네이버 API가 NAVER API HUB로 이관된 사실 확인

- 네이버 지역검색 API 발급 절차를 조사하던 중, 네이버 개발자센터 공지([article/32530](https://developers.naver.com/notice/article/32530))를 통해 Search API(지역검색 포함)·Search Trend·Shopping Insight가 NAVER Cloud Platform(NCP)의 **NAVER API HUB**로 이관되고 있음을 확인
- 이관 일정: 2026-06-25 API HUB 출시 → **2026-07-31부로 기존 개발자센터 신규 신청 차단** → 2027-06-30 개발자센터 완전 종료(그 이전 발급 키만 유예)
- 오늘(2026-09-21) 기준 이미 신규 신청 차단 시점을 지났기 때문에, 예전 방식(developers.naver.com에서 애플리케이션 등록)으로는 새 키를 받을 수 없고 **NCP 계정 가입 → NAVER API HUB에서 신청**하는 절차로 진행해야 했음

### 3. 카카오 로컬 API vs 네이버 지역검색/검색어트렌드 — 무엇을 먼저 붙일지 결정

- 네이버 지역검색 API는 카카오 로컬 API와 응답 성격이 거의 동일(상호명·주소·카테고리만 제공, 평점·리뷰 없음)해서 **기능이 중복** → 우선순위를 낮춤
- 반면 검색어트렌드(구 데이터랩) API는 계획서상 "카카오/네이버가 장소 데이터를 주고, 트렌드 데이터가 그 장소를 지금 다룰 가치가 있는지 판단하는 필터" 역할을 하는 **핵심 조합 요소**라 대체재가 없음 → 네이버 쪽은 지역검색 대신 검색어트렌드 API를 먼저 연동하기로 결정

### 4. NAVER API HUB 검색어트렌드 API 스펙 확인 및 연동

- [API HUB 문서](https://api.ncloud-docs.com/docs/naver-api-hub-search-trend-examples)에서 정확한 엔드포인트/인증 방식 확인:
  - `POST https://naverapihub.apigw.ntruss.com/search-trend/v1/search`
  - 헤더: `X-NCP-APIGW-API-KEY-ID`(Client ID), `X-NCP-APIGW-API-KEY`(Client Secret)
  - 바디: `startDate`/`endDate`/`timeUnit`/`keywordGroups`/`device`/`ages`/`gender` — 기존 데이터랩 API와 요청 스키마 자체는 동일, 도메인·인증 헤더만 변경됨
- 참고 파일: `apps/research-collector/src/test-naver-trend.js`

### 5. 스모크 테스트 스크립트 2종 작성

## 🐛 발생한 문제 & 해결

### 문제 1: 카카오 로컬 API 호출 시 403 `OPEN_MAP_AND_LOCAL service` 에러
- **원인**: REST API 키 발급만으로는 로컬(장소) 검색이 활성화되지 않음. Kakao Developers 콘솔에서 앱의 "카카오맵" 제품을 별도로 켜야 로컬 API가 열림
- **해결**: 앱 콘솔 → "제품 설정" → "카카오맵" 활성화(ON) 후 재호출 → "강남 야장" 키워드로 15건 정상 응답 확인
- **참고**: `apps/research-collector/src/test-kakao-local.js`

### 문제 2: 네이버 API 발급 절차가 기존에 알던 방식(개발자센터 애플리케이션 등록)과 다름
- **원인**: 2026-07-31부로 네이버가 Search API 계열의 신규 발급을 개발자센터에서 NAVER API HUB(NCP)로 완전히 옮김. 이 사실을 모르고 진행했으면 이미 막힌 경로로 계속 시도했을 것
- **해결**: 공지사항 원문을 직접 확인해서 이관 일정과 변경사항(인증 체계, 계정 체계가 NAVER 계정→NCP 계정으로 바뀜)을 파악한 뒤 NCP 계정을 새로 만들어 API HUB에서 발급

## 💡 배운 점 / 메모

- 외부 API를 "예전에 봤던 문서 기준"으로 연동하기 전에, 발급 페이지에서 최신 공지사항을 먼저 확인하는 습관이 필요함 — 네이버처럼 플랫폼 자체가 옮겨가는 경우 예전 가이드대로 하면 아예 진입이 막혀 있을 수 있음
- 지도/로컬 계열 API는 "키 발급"과 "서비스(제품) 활성화"가 분리된 경우가 있다 — 카카오는 REST API 키 자체는 앱 생성 시 자동 발급되지만, 카카오맵·메시지 등 개별 제품은 콘솔에서 켜야 실제 호출이 가능
- 비슷해 보이는 API 두 개(카카오 로컬 vs 네이버 지역검색)를 무조건 둘 다 붙이기보다, 응답 스키마를 먼저 비교해서 겹치는 기능이면 하나는 보류하는 판단이 실제 구현 범위를 줄여줌
- API 응답 검증은 "에러 없이 200이 왔다"가 아니라 "결과 값이 질의 의도와 맞는가"까지 봐야 함 — 카카오 키워드 검색은 정확 매칭이 아니라 관련도 기반이라 "야장"을 검색해도 야외 좌석 여부는 응답만으로 확정할 수 없다는 한계를 확인함
